# ADR-0038：诊断 Agent 自己写循环，报告的证据由程序渲染

- 状态：已采纳
- 日期：2026-11-24

## 背景

3d 要做一个最小的诊断 Agent：告警触发后用只读工具查一轮，交一份带证据的报告，全过程落盘。它要跟着阶段 4 的每次故障实验一起跑，阶段 6 再做评测。约束：

- 工具要查的 Prometheus、Loki、kube-apiserver 都在家里的集群里，外面够不着。
- 这个项目里循环本身是要学的东西（终止条件、步数和费用的上限、留痕）。
- Claude 的 Agent SDK 没有 Go 版本。
- 当前的模型有两条和循环直接相关的硬约束：思考块绑定在产生它的那段对话上，历史只能在末尾追加；不能强制模型调用某个工具（`tool_choice` 的 `any`、`tool` 返回 400）。

细节和查到的事实见[设计文档](../design/3d-diagnosis-agent.md)。

## 决定

1. **循环自己写，用 Messages API。** 循环只认一层自己定义的接口（`internal/llm` 的 `Conversation.Send`），对话的历史收在接口的实现里：循环拿不到历史，也就没有机会去改它。“只追加”由结构保证，不靠自觉。
2. **上限是软的。** 轮数、费用、时长撞到之后不直接断掉，而是再给模型最多两轮、不执行任何查询，让它用已有的证据交报告，结束原因记成 `reported_truncated`。
3. **报告经 `submit_report` 工具交，证据由程序渲染。** 每次工具调用由程序编一个步骤号写在结果的开头；报告里每条证据引用步骤号；程序核对引用的步骤存在并且没有出错，报告里的“查询和结果”从运行记录里取，不采信模型自己写的数。不合格打回一次，再不合格按原样收下并标成 `unverified`。
4. **工具输出在进入历史之前裁剪**，裁掉了什么写在结果里，原始结果另存一份。
5. **每次运行落一份只追加的记录**（`events.jsonl` 加原始结果），回放只读磁盘。
6. **Agent 是加在 `alertsink` 旁边的第二个 webhook 地址，不替换它**：`Watchdog` 的心跳不该依赖一个要调外部 API 的程序。

## 备选方案

- **SDK 的 Tool Runner**（beta）：循环在 SDK 里，省代码。没选：上限、收尾、报告的校验都要插在循环中间，而且要学的就是这一段。
- **Managed Agents**（beta）：循环和工具的沙箱都在 Anthropic 那边。没选：沙箱够不着家里的集群，三个工具都得做成由我们回传结果的自定义工具，循环省了、留痕却不在自己手里；另外按会话时长收费。
- **撞到上限直接结束**：实现简单。没选：花掉的钱和查到的东西全部作废，而故障实验里最容易撞上限的恰恰是最复杂、最想看报告的那几次。
- **最后一轮用结构化输出（`output_config.format`）交报告**：没选：它约束的是每一轮的文字输出，和中间的工具调用轮次混在一起不好用；工具加 `strict` 同样保证结构合法。
- **让模型自己在报告里写查询和结果**：没选：抄错、编造都发现不了，“每条结论附查询和结果”就成了一句没人核对的要求。
- **事后裁剪历史里旧的工具结果来省 token**：没选：改写历史会让后面的思考块和缓存的前缀一起失效。一次运行被轮数和费用卡住，到不了需要它的长度。

## 后果

- 好处：每一步都在自己手里，记录的格式自己定；“能不能溯源”是程序判的，阶段 6 的指标“无法溯源的结论比例”现成；换模型或者换后端只动 `internal/llm` 的一个实现。
- 代价：上限是软的，最坏的时长约是上限加一次工具的时限再加两次模型调用的时限，最坏的费用是上限加收尾那两轮的。
- 代价：费用是按代码里的价格表估的，价格变了要改表；发生拒绝回退时只算了最后作答的那一次，被拒绝的那一次没有算。账单以 Console 为准。
- 代价：开了服务端的拒绝回退，整个循环走 SDK 的 beta 命名空间。
- 没有解决：程序只能核对“引用的步骤存在”，核对不了“这一步的结果是否真的支持这条结论”。那要靠阶段 6 的判分器。
- 重新评估的时机：Go 有了官方的 Agent SDK；或者阶段 4 里发现一次运行经常撞到上下文长度而不是费用，那时再看压缩。
