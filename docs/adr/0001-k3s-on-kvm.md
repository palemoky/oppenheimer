# ADR-0001：在 KVM 虚拟机上用 k3s 搭集群

- 状态：已采纳
- 日期：2026-11-11

## 背景

需要一个能演练节点宕机和网络分区的多节点 K8s 集群。可用的主力机器是一台 32GB 的 Ubuntu，上面还要跑 Kafka、多套 MySQL 主从、Redis Cluster、Prometheus 和 SkyWalking，内存偏紧。

## 决定

在 Ubuntu 上用 KVM 创建 3 台虚拟机，安装 k3s，1 server + 2 agent。

## 备选方案

- **kubeadm**：更接近企业自建集群，能学到控制面各组件的手工部署。但控制面占用更多内存，而日常使用层面与 k3s 没有区别。
- **kind 或 k3d（容器当节点）**：最省资源，但节点是容器，关节点、断网络的故障不够真实。
- **裸机单节点**：没有节点级故障可练。
- **把 Mac mini 加进集群**：会变成 arm64 与 x86_64 混合集群，所有镜像都要多架构构建，麻烦与学习目标无关。

## 后果

- 省下的内存留给中间件和监控。
- 缺少 kubeadm 手工搭建的经验，需要的话可以之后单独练一次。
- k3s 默认用 SQLite 或内嵌 etcd、自带 Traefik 和 ServiceLB，与标准发行版有差异，阶段 2a 需要明确哪些自带组件保留、哪些替换。
