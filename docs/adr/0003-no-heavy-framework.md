# ADR-0003：不使用重型微服务框架

- 状态：已采纳
- 日期：2026-11-11

## 背景

Go 微服务可以用 go-zero、Kratos 这类全家桶框架，也可以用基础库自己组装。

## 决定

用基础库组装：对外 HTTP 用 gin，服务间用 grpc-go，限流熔断用 sentinel-go，其余（配置、日志、中间件链、服务发现、优雅启停）自己写薄封装放在 `pkg/`。

## 备选方案

- **go-zero**：自带代码生成、限流、熔断、缓存封装，上手快，国内使用广。
- **Kratos**：分层清晰，生态完整。

两者都会把超时传递、重试、熔断、负载均衡这些机制藏在框架里。

## 后果

- 这些机制要自己接一遍，正是要学的东西。
- 初期搭建更慢，需要自己保持各服务结构一致。
- 如果目标岗位明确使用某个框架，之后可以用它重写一个服务做对比。
