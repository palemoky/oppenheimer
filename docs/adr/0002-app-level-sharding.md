# ADR-0002：应用层实现分库分表

- 状态：已采纳
- 日期：2026-11-11

## 背景

订单数据要分库分表。项目的目的是学习，需要理解分片路由、非分片键查询、扩容这些问题本身，而不只是会配置一个中间件。

## 决定

在应用层自己实现分片路由（`pkg/sharding`）：

- 初始 2 库 × 4 表，每个分片一主一从。
- 以用户 ID 为分片键。
- 订单号中嵌入用户 ID 的分片基因，使按订单号查询也能直接定位分片。

分片数、基因位数等细节在阶段 1c 动工时补充到本文。

## 备选方案

- **ShardingSphere-Proxy**：对应用透明，功能全。但路由逻辑成了黑盒，而且多一个需要运维的组件。
- **ShardingSphere-JDBC**：只有 Java。
- **Vitess**：功能强大但很重，对这套硬件来说占用太多。
- **TiDB 等分布式数据库**：回避了分库分表问题，学不到要学的内容。

## 后果

- 分片逻辑完全可见，面试时能讲到实现细节。
- 跨分片查询、分布式分页、扩容迁移都要自己处理，工作量更大，这也是学习内容的一部分。
- 阶段 1c 完成后可以选做：接入 ShardingSphere-Proxy 做一次对比。
