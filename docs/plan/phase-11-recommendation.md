# 阶段 11：推荐（可选）

**目标**：先做一条能跑通的最小推荐链路（召回、排序、兜底），弄清推荐系统的工程骨架；之后有需求再按方向深入。
**说明**：可选阶段，只到里程碑粒度，动工前再细化。分两段：11a 是入门，做完就可以停；11b 是一组互相独立的深入方向，按需要挑。依赖阶段 1 的订单数据和阶段 3 的压测、指标。**建议紧跟在阶段 5 之后做**，检索那一层直接复用（见下面“和诊断 Agent 复用的部分”）。

**边界**：这个项目练的是推荐系统的工程，不是算法。

- 排序只做到“能跑、可替换”（规则打分或一个很小的模型），不追求效果，也不在这里学深度学习。
- 系统里没有真实的用户行为。行为数据要自己生成，生成器里预先埋下已知的偏好（例如用户分群，各群偏好不同的类目），这样才能检验推荐有没有把它找出来。**在生成的数据上得到的效果数字不代表真实效果，只用来验证链路是通的。**
- 商品只是灌进去的模拟目录（类目、价格、标题），不做商品管理（见 `GOALS.md` 的非目标）。

## 和诊断 Agent 复用的部分

阶段 5b 的“runbook 与历史复盘检索”和推荐的召回是同一条链路：把内容变成向量、建索引、按相似度取回一批候选、再排一次序。能复用的和不能复用的要分清：

- **能复用**：生成向量的那一层（调哪个模型、批量、缓存、失败重试）；“召回一批再重排”的接口和代码骨架；离线评测的做法（准备带标准答案的查询集，算 recall@K 这类指标，每次改动跑一遍对比），和 5a 的评测流水线是同一个思路；用模型给候选打分（5b 的“封闭式判断交给决策模型”实验，换个提示就是重排）。
- **不能直接复用**：索引本身。复盘和 runbook 只有几十到几百篇，逐个算相似度就够了，关键词检索往往比向量更管用；商品是十万以上，才需要近似最近邻索引。所以共用的是接口和评测，索引各用各的。
- **反过来的方向**：把推荐接口做成 Agent 的一个工具，就是对话式推荐（放在 11b）。

做法：5b 写检索时就按“可以给别的内容用”来设计（内容的类型、向量的来源、索引的实现都能换），放在公共的位置；11a 接着用，只换索引。如果先做了 11a，反过来也一样。

## 11a 入门

- [ ] 写设计文档和 ADR：召回用哪几路、向量从哪来、索引用什么、放弃了什么。动工前核对集群剩余的内存
- [ ] 模拟的商品目录和购买历史生成器（埋入已知的偏好）；行为只用“下单”这一种，不采集曝光和点击
- [ ] 离线任务：热门榜、商品共现（“买了又买”，协同过滤最简单的形式）、商品向量和索引
- [ ] recommend 服务：三路召回（热门、共现、向量）并行调用，每一路单独设时限，超时的丢掉；合并、去重、过滤掉买过的；规则打分排序；同类目打散。对外接口先改 OpenAPI 规范
- [ ] 兜底：任何一路不可用时退到热门榜，推荐整体不可用时不影响下单；按 1d 的做法登记开关。指标和链路按现有规范接入
- [ ] 离线评测：在埋了偏好的数据上和“随机”“纯热门”对比
- [ ] 压测推荐接口，量出延迟和吞吐

**验收标准**

- 在埋入了已知偏好的数据上，推荐结果明显好于随机和纯热门（例如命中用户所在分群偏好类目的比例）。
- 任何一路召回不可用时接口仍然返回结果，下单链路不受影响。
- 推荐接口有延迟和吞吐的基线；向量检索的召回率、延迟、内存有实测数据。

## 11b 深入方向（按需要挑，互相独立）

- **实时特征**：消费行为事件，算用户最近的下单序列、商品近 N 分钟的热度，在线读取；弄清离线算的特征和在线读到的不一致会带来什么。和阶段 7 风控的实时特征是同一类问题，**放在阶段 7 之后做，复用它的做法**。
- **行为采集**：曝光、点击进 Kafka。量比订单大一到两个数量级，丢一点可以接受，和订单事件的可靠性要求不同，写入链路可以不一样。
- **实验分流**：按用户分桶、分层实验、指标按桶统计。桶号进指标标签是有限的枚举，可以；用户号不行。
- **向量检索深入**：HNSW 和 IVF 的取舍（召回率、延迟、内存、构建时间），对比独立的向量库和已有组件的向量能力，索引的增量更新。
- **对话式推荐**：推荐和商品检索做成工具，由 Agent 根据对话调用；评测沿用阶段 5 的做法。
- **用模型重排**：候选交给语言模型或决策模型打分，和规则打分比效果、延迟、费用。
- **缓存**：推荐结果能不能缓存、缓存多久，和“刚买过的还在推”之间怎样取舍。
- **延迟预算**：给整条链路定 P99 的预算，排序批量取特征，用压测守住。

## 面试考点

推荐系统的整体架构（召回、粗排、精排、重排各解决什么）；协同过滤的原理和冷启动；向量检索的 HNSW、IVF、量化；推荐的召回和检索增强生成里的检索有什么相同和不同；特征平台与线上线下一致性；实时特征的延迟和窗口；A/B 实验的分流、分层和显著性；信息流的去重与已读过滤（布隆过滤器）；多路调用的超时与降级；推荐结果的缓存；热门榜的实时计算（滑动窗口、Top K）。
