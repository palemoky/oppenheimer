# 阶段 10：LBS（可选）

**目标**：给订单系统加上“位置”这个维度，练习空间索引、高频位置写入和就近匹配。场景定为同城即时配送：用户找附近的门店下单，订单按距离派给骑手。
**说明**：可选阶段，只到里程碑粒度，动工前再细化。依赖阶段 1 的服务和阶段 3 的压测、指标；和阶段 7、8、9 互相没有依赖，排在哪里都可以。门店和骑手都是灌进去的模拟数据，不做门店管理、骑手端、路径规划和真实地图（见 `GOALS.md` 的非目标）：距离先用球面直线距离，要不要接路网在动工时定。

**为什么是同城配送而不是打车**（2026-11-18，主人问过）：两者共有“移动对象的位置上报”和“就近派单”，这两块做哪个都一样。区别在其余的部分：

- 同城配送接在现有的系统上：门店、库存、下单、支付都已经有了，只是在下单链路上加位置。打车没有门店和库存，“订单”是一段行程，等于另起一套系统，阶段 1 的东西基本用不上。
- 同城配送多出“附近的门店”（静止的点、读多写少）和“配送范围”（点在多边形内）这两类空间问题，打车只有移动的点。空间索引的几种做法在配送场景里能比得更全。
- 打车独有的是按轨迹计费、动态调价（供需比）、行程中的实时位置共享和预估到达时间。这些更偏业务和算法，其中预估到达时间和调价离不开路网和真实数据，在这个项目里做不出有说服力的结果。

打车特有的考点（司机和乘客的双向匹配、调价）记在下面的面试考点里，只要求讲得清，不实现。

## 候选方向（动工时选定，前三个是主线）

- **附近的门店（读多写少）**：按“坐标加半径”或“坐标加配送范围”查门店。对比几种空间索引：GeoHash 前缀（MySQL 普通索引就能做）、Redis GEO（有序集合加 GeoHash）、MySQL 的空间索引（R 树）、Google S2 或 Uber H3 的格子编号。重点弄清 GeoHash 的边界问题（相邻的两个点前缀可以完全不同，要查周围 8 个格子）和格子大小怎样选。
- **配送范围的判断**：门店的配送范围是多边形，下单时判断收货地址在不在范围里（点在多边形内），放进下单链路要守住现有的延迟预算。范围变更后缓存怎样失效。
- **骑手位置上报（写多）**：每个骑手几秒上报一次，是这个阶段的高并发部分。位置只保留最新值还是留轨迹、上报走 HTTP 还是长连接、要不要先进 Kafka 再落到索引、过期的位置怎样清掉（骑手下线后不能再被派单）。
- **派单**：订单付款后在附近的骑手里选一个。从“最近的空闲骑手”做起，再看批量匹配（攒一小段时间的订单和骑手一起分配）。**一个骑手不能同时被派两单，这是和库存扣减同一类的一致性问题**，按 `AGENTS.md` 由 Fable 编写或评审；派单的状态并进订单状态机还是单独成表，写 ADR。
- **地理围栏**：骑手进入门店或收货地址的范围时触发事件（到店、送达），流式地判断“进入”和“离开”。
- **按地理位置分片**：位置数据按城市或格子分片，热点区域（商圈）的倾斜怎样处理；和 1c 按用户分片的订单库怎样配合。

## 任务

- [ ] 选定方向和场景边界，写设计文档和 ADR（空间索引选哪一种、放弃了什么）
- [ ] 数据：门店、配送范围、骑手的表结构和模拟数据生成器（位置分布要有商圈式的聚集，均匀分布测不出热点）
- [ ] location 服务：附近的门店查询、配送范围判断；对外接口先改 OpenAPI 规范
- [ ] 骑手位置上报的写入链路和位置索引，过期清理
- [ ] 派单：就近匹配、骑手的占用与释放、超时未接单的改派，全流程幂等
- [ ] 接入下单链路：下单时校验配送范围；location 不可用时的降级（按 1d 的做法登记开关）
- [ ] 指标和链路按现有规范接入（坐标、门店号、骑手号不进指标标签）
- [ ] 压测：附近查询的读压测、位置上报的写压测、高峰期派单；故障实验：位置索引所在的 Redis 不可用、派单进行中杀掉服务

## 验收标准

- 附近查询的结果正确：和“全表逐个算距离”的结果对比，没有漏掉边界附近的门店。
- 任何压测和故障场景下，一个骑手同一时刻最多有一个进行中的派单；没有“订单已付款却永远没人接”的单子（超时会改派或进入可查的失败状态）。
- 几种空间索引的对比有实测数据（查询延迟、写入吞吐、内存）。
- 附近查询和位置上报各有延迟和吞吐的基线。

## 面试考点

GeoHash 的原理、精度和边界问题；Redis GEO 的实现（有序集合、52 位的 GeoHash）和 `GEOSEARCH` 的复杂度；R 树、四叉树、S2、H3 各自的特点和适用场景；“附近的人”怎样设计；海量位置上报的写入链路；派单的并发控制与全局最优（贪心和批量匹配的取舍）；地理围栏；按地理位置分片与热点区域；打车和配送在派单上的区别（司机接完一单才空闲，骑手可以顺路带多单）；动态调价的思路（按格子统计供需比）。
